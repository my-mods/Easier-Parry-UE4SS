# Native dodge guard recovery

The snapshots target Steam build 25129649 / CL-257186. Original assets and hashes are in `upstream/guard`.

Only `GA_Dodge` is shipped in the native container. It adds the existing `Player.Input.BlockTagAbilities` tag to `ActivationOwnedTags`. The engine owns this suppression for the dodge ability’s lifetime and removes it on end or cancellation. Forward dodge checks the native combat state after applying its effect. While the state is dodge (8), it starts the same native WaitDelay completion task used by side/back dodges, using Get Invincibility Time and the existing OnStateChanged listener. Either completion path releases suppression; a missing state-change event cannot leave forward suppression active indefinitely. A failed start ends immediately. Forward completion does not remove invincibility tags it never granted; cancellation unregisters the listener even when the invincibility flag is false. Stamina checks, animation selection, effect application and stock guard input handling are unchanged.

`GA_Input_CombatBlock.json` is an unmodified stock reference, excluded from the container. The game’s own guard ability listens for suppression-count changes: it lowers desired guard while the count is nonzero and restores it when the count reaches zero, provided the ability is still active.

Stock attacks retain both original paths: a successful combo handoff ends guard immediately; an attack release arms a listener that ends guard on the next attack press. The release listener fires immediately if attack is absent when guard starts, so guard-first input also arms cancellation for the first attack. If attack is already held when guard starts and its combo handoff fails, guard remains active until a subsequent release/press or another stock cancellation. Actual guard release and ability cancellation retain stock teardown. Once guard has ended, dodge completion cannot restart it without a fresh guard input.

Forward completion uses the native GetCurrentState getter and existing state-change and ability-end paths. It adds no guard bytecode, Lua hooks, polling or object searches. Forward dodge now also starts the existing native ability timer, using the game-configured duration rather than a fixed mod delay. It leaves stock guard listener lifetimes intact. It conflicts with other replacements of `GA_Dodge`; a separate mod replacing guard input can change its response to the suppression tag.

The separate Mod Settings toggle leaves this cooked payload unchanged. With Dodge while blocking Off, `Scripts/DodgeSettings.lua` adds the existing `Player.Input.Block` tag to the current player's instanced dodge ability's `ActivationBlockedTags`. It discovers that instance through the player's ability system, with bounded work after save loading or relevant lifecycle events. Shared class defaults, activation-owned suppression tags and other actors are unchanged. The session restores only the added blocking requirement before applying a new settings snapshot. With the toggle On, the additional setup module is not loaded. There is no recurring settings or input check and no Lua callback on each dodge.

To reproduce the native payload, convert `src/guard/GA_Dodge.json` to a UE5.5 legacy asset using UAssetAPI-compatible JSON conversion, preserve its `/Game/_Dawnwalker/Combat/Abilities/Dodge/GA_Dodge` package path, and convert it to an UE5.5 IoStore container with retoc and the matching game script-object metadata. Do not include the stock guard reference in that container.
